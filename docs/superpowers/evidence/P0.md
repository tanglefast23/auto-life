## Kill-gate record: expo-sqlite web is out; KV adapter is in

The plan named Task 4 a kill gate and it fired:

1. **First failure — CanvasKit path.** `LoadSkiaWeb()` fetched `/_expo/static/js/web/canvaskit.wasm` (404). Fix: `LoadSkiaWeb({ locateFile: (f) => '/' + f })` against the root copy that `setup-skia-web public` installs. (Also: the CLI needs the explicit `public` argument; the bare form errors.)
2. **Second failure — expo-sqlite on web.** With isolation true and wasm assets correctly present in `dist/assets/…/wa-sqlite/`, `openDatabaseAsync('proof.db')` hung indefinitely (instrumented: stuck at "opening…", 15 s timeout; the worker spawned from a `blob:` URL and never fetched its wasm). The official docs state web support "is in alpha and may be unstable" and our setup matched their requirements (wasm assetExts + COEP/COOP), so this is the documented instability, not a config error.
3. **Ruling (per the plan's kill-gate instruction):** persistence goes behind `src/persistence/kv.ts` — an async KV interface. **Web driver = localStorage** (v1 persists one small versioned JSON blob, SPEC §15; well inside limits). **Native driver = expo-sqlite** (stable there; HFM-proven), same interface, Metro platform resolution selects. Revisit sqlite-web only if a future version needs relational queries on web.

## Deviations from the plan text (recorded, not hidden)

- `setup-skia-web` → `setup-skia-web public` (scripts updated).
- `serve.json` must live inside `dist/` — `export:web` now copies it (root copy remains the source of truth; `vercel.json` mirrors it for the eventual host).
- Metro's `server.enhanceMiddleware` is deprecated/inert in SDK 57's dev server — dev-mode runs **without** isolation headers. Harmless for P0 (the gate runs against the exported artifact, which has them via `serve.json`) and moot for SQLite now that web uses localStorage. Noted so nobody trusts dev-mode for isolation-dependent work.
- Dev-mode visual check was superseded by the exported-artifact check (the stronger claim) after the middleware finding made dev headers unattainable.
