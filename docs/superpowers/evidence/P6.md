## T1 — art gates

`validate-palette` previously checked colour **membership only**, which is why
`build-atlas.ts` carried a comment recording that an adversarial pass caught Ink-outlined
world art while the validator reported green. Added, with tests:

- `findOutlineRoleViolations` — design.md §3 Track B, mechanically. Character sprites are
  exempt and the exemption is justified in code: §2 defines `HAIR_BLACK`'s shadow as Ink,
  so a black-haired sim is correctly Ink-outlined.
- `boxiness` — a plain filled rectangle scores exactly 1.0. This is "I just see a square"
  as a failing test.
- `silhouetteSignature` — colour-blind by design, so two colour-only variants collide.
- `opaqueIslands` — closes A0's detached-mitten deferral structurally.
- `encodeIndexedPng` / `decodePng` — see the T13 entry; written, tested, **not shipped**.

**Findings the gates caught that review would not have:**

1. Walk frames 0 and 2 were byte-identical — `lift = [0,1,0,1]` made a four-frame cycle
   really a two-frame one. At 1× that reads as a slightly stiff walk.
2. The profile walk's swinging arm was drawn *inside* the torso outline, so it could never
   change the silhouette; the two contact frames were identical.
3. Transparent notches kept residual RGB, which the indexed round-trip rejected.

**Findings only the review sheet caught:**

1. A 10px torso under a 14px head read as a stick with a balloon on top → widened to 12.
2. The tunic stopped at the waist and read as underwear → extended to the hips.

## T8–T10 — audio

25 cues, **1.99 MB**, mono 22.05 kHz, rendered from authored parameters and committed.
`npm run audio:check` diffs a fresh render against the bank exactly as `art:check` does.
SPEC §14's set in full: day and evening beds crossfading on the same minute the tiles do
(both read `EVENING_START_MINUTE`, and the content gate asserts `audio.json` agrees), four
level-dependent Practice riffs, room tone plus the rain variant, footsteps per material,
eight activity loops, six UI cues.

**A real bug the tests caught:** `playLoop` is idempotent per key — which is what stops a
repeated minute restarting the music — so reusing one `music.bed` slot meant the 19:00
change re-called a live voice and returned early. The evening bed never started at all.
Keyed per variant now, and the incoming bed starts before the outgoing is removed.

**Browser autoplay**, which an audit flagged and no test could have: Chrome blocks playback
before a gesture, and a rejected `play()` counted as started would have left the frozen
playtest running silent forever. A rejected play now stays pending and the first gesture
recovers it.

## T0A — NOT SHIPPED, with a verified reason

HFM §1.4 says do not block the whole app on CanvasKit, and this repo does exactly that.
The fix was written and **reverted**: `@shopify/react-native-skia` 2.6.2 constructs its web
API at *module import*, so importing `App` above the loader gate permanently builds Skia
against an undefined CanvasKit. Applying the lesson properly needs `WorldScene` behind
`React.lazy` so the Skia module is not imported until the world renders.

**Owner: v1.1.** Recorded rather than rushed.

## T13 — indexed PNG: NOT SHIPPED, with a verified reason

design.md §2 asks for indexed PNG; P3 deferred it here. `encodeIndexedPng` works — its
round-trip is proven in `art-gates.test.ts`, and Chrome decodes its output correctly
(colour type 3, 1024×420, 15,256 bytes against 22,019 for RGBA).

**CanvasKit does not decode it.** `useImage` returned null forever, `WorldScene` rendered
nothing, and the world was blank **with no console error** — the silent-blank failure P0's
kill-gate exists to catch, reached from a new direction. Every test was green throughout;
only opening the exported build in a browser found it.

The encoder stays, tested and unused. This is a container change only: the palette
validator enforces §2 membership on every pixel either way. **Owner: v1.1**, with the Skia
version.
