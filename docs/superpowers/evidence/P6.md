**A real bug the tests caught:** `playLoop` is idempotent per key — which is what stops a

playtest running silent forever. A rejected play now stays pending and the first gesture
recovers it.

## T0A — NOT SHIPPED, with a verified reason

HFM §1.4 says do not block the whole app on CanvasKit, and this repo does exactly that.
The fix was written and **reverted**: `@shopify/react-native-skia` 2.6.2 constructs its web
API at *module import*, so importing `App` above the loader gate permanently builds Skia
against an undefined CanvasKit. Applying the lesson properly needs `WorldScene` behind
`React.lazy` so the Skia module is not imported until the world renders.

**Owner: v1.1.** Recorded rather than rushed.

## T13 — indexed PNG: NOT SHIPPED, with a verified reason

design.md §2 asks for indexed PNG; P3 deferred it here. `encodeIndexedPng` works — its
round-trip is proven in `art-gates.test.ts`, and Chrome decodes its output correctly
(colour type 3, 1024×420, 15,256 bytes against 22,019 for RGBA).

**CanvasKit does not decode it.** `useImage` returned null forever, `WorldScene` rendered
nothing, and the world was blank **with no console error** — the silent-blank failure P0's
kill-gate exists to catch, reached from a new direction. Every test was green throughout;
only opening the exported build in a browser found it.

The encoder stays, tested and unused. This is a container change only: the palette
validator enforces §2 membership on every pixel either way. **Owner: v1.1**, with the Skia
version.

## T11 remainder — the motion table wired to its surfaces (2026-07-31)

The earlier T11 entry left seven of eight motions defined, tested, and connected to
nothing. `motion.test.ts` was green throughout, because it asserts what the table
*contains*; a tested table with no consumer is indistinguishable from a finished feature
when you are reading test output.

| Motion | Surface | Note |
|---|---|---|
| `cardSlide` | `QueueStripCards.EnteringUnit` | Arrival needs no diff — a card that entered is a component that mounted |
| `cardRemove` | `QueueStrip` ghost layer | Departure does: the card is gone from the snapshot before the strip re-renders |
| `poof` | same ghost layer | Four square puffs, drawn outside the card's own clip |
| `sparkle` | `WorldScene.RewardSparkle` | At the granted decoration's placement; the only gold motion in the game |
| `urgentPulse` | `QueueStrip` | Replaces a hard-coded 500 ms and a second local `reducedMotion` branch |
| `recapSlide` | `FirstSessionPanels.MorningRecap` | Keyed on `recap.forDay`, so it does not twitch on every parent render |
| `queueGlance` | `WorldScene` → `buildCharacterQuad` | Facing override, presentation-only; `render-view.ts` stays the sole deriver |
| `lightingCrossfade` | `WorldScene` | Already wired |

**The discriminator for the poof is the recap, not `currentCardId`.** Stop and finish both
empty the same slot, so keying on the current card would reward a cancel with the animation
that means "well done". `session.recap.completedActivityIds` distinguishes them, and the
day-boundary reset is handled explicitly so midnight does not poof the whole queue.

**Ghosts are outside `visualRows`** — keyboard focus, drag indices, and every existing mount
assertion read that list, and they carry their own `queue-ghost:` test ids so a departing
card cannot make an existing `findByProps` ambiguous.

**`queueGlance` does not use `forecastRevision`.** That was the obvious trigger and the
wrong one: the forecast cache also revises on every new game hour, which at 1× is a glance
a minute for no player action. It reads a signature of the queue's card ids instead.

**New gate, and the one that matters most here:** `motion.test.ts` now walks source and
fails if any table entry has no consumer, and fails if a file that animates names a motion
without routing through `resolveMotion`. That is the check whose absence let this ship
half-wired.

## T13 — ship pass (2026-07-31)

### Findings

**1. CI has never run. Not a code failure — a billing block.** SPEC §18's technical DoD
requires the harness and both goldens "green in CI". `.github/workflows/ci.yml` exists and
runs `npm run verify` on push and PR, which is the right gate. Every run since 2026-07-30
has failed in 2–4 seconds with, verbatim: *"The job was not started because recent account
payments have failed or your spending limit needs to be increased."* Five consecutive runs,
including `da590c8`. **Action is Joe's** — GitHub billing settings — and no code change can
clear it.

**2. The bill of materials only ran in one direction.** Every assertion asked "does an asset
exist for what the game declares?"; none asked "can the game reach every asset we authored?"
So art that nothing can display passed the whole gate — a placeholder from the opposite
side.

Found by it: **the `idle` pose is unreachable, and with it 20 sprites.** `render-view.ts`
derives pose from `s.current`, and an `idle`-kind activity never becomes current —
`step.ts:1330` removes the card and returns null, which reads as `stand`. Verified by a
seven-day seeded run at 4×: pose `idle` occurred in **0 of 10,080 ticks**, and the queue was
empty for **0** of them. The cost is `idle` (2 frames) plus `idle-window-gazing`,
`idle-slow-stretching` and `idle-air-guitar` (1 each), across 4 appearances.

That matters beyond the sprite count: `window-gazing` and `slow-stretching` are identity
preferences, and **`air-guitar` is the whole of Goal 4's reward**. The game grants all three
and can display none of them.

The `idle` branch dates to P2 (`886d806`), so this is **not** caused by the rolling routine
queue — that feature only removes the last situation in which an empty queue might have led
somewhere. Making idle reachable is a design decision (*when* should she idle?) and a
mechanics change, so it is **Joe's call, not the ship pass's**. `bill.test.ts` now carries
the reachability gate with this exact set as a named exception, so a *new* unreachable pose
fails immediately and this one cannot be forgotten.

**3. The mixer was untested.** SPEC §18 requires "audio mixes with working sliders".
`audio-bus.test.ts` covers P5's deliberately silent stub and `cue-router.test.ts` covers
which cue fires — nothing covered `ExpoAudioBus`, the class that turns three sliders into a
volume. Closed: 15 tests over the mix arithmetic (master × channel × authored gain, mute
winning and unmute restoring rather than jumping to full), the autoplay recovery path, and
the shutdown contract — including that a late `unlock()` cannot resurrect a closed tab's
audio.

### ⚠ BLOCKER — the audio system never runs in the shipped build

Not quiet. **Never invoked.**

1. Across a full simulated day — wake, activities, a wrinkle, a decoration grant, card
   inserts, and the 19:00 bed change — the browser loaded **6 resources in total**: two JS
   bundles, `canvaskit.wasm`, two `.ttf` faces and the atlas PNG. **Not one audio file.**
   The resource buffer was 6 of 250, so this is not a truncation artefact.
2. All **25 `.wav` files are present in `dist/assets/assets/audio/`** and `AUDIO_ASSETS`
   resolves them. The assets shipped; nothing ever asked for them.
3. Not muted — the HUD button reads "Mute everything", i.e. the *available* action.
4. Autoplay was unlocked: a probe `AudioContext` reported `state: "running"`.
5. `AudioBufferSourceNode.prototype.start` and `HTMLMediaElement.prototype.play` were
   patched, then a card was inserted through a real click. The card appeared in the queue.
   **Neither patch fired.**

**Root cause, located:** `cueRouter` is constructed at `ApplicationRoot.tsx:149` and
**referenced nowhere else in the repository**. Its entry points — `onMinute`, `onEvents`,
`onFootstep`, `setPaused`, `setHydrating`, `bedFor` — have no caller outside
`cue-router.ts` and its own tests.

**This is the same defect as T11's**, in the ring the phase called finished: a complete,
fully tested component wired to nothing. The suite cannot see it, because
`cue-router.test.ts` drives the router directly against a fake bus and
`expo-audio-bus.test.ts` drives the bus directly — each unit is exercised, and the
composition between them is not. The T11 orphan gate added in this phase catches exactly
this class **for motions only**; the equivalent check for audio does not exist and should.

**Consequence: "Milestone B (audio) done and gated" was false.** The bill gate proved a
real file exists per declared cue, which is what it claims to prove, and no gate ever asked
whether a cue can reach a speaker.

The wiring looks tractable — `GameLoop` already exposes an `onEvents` observer it calls
every tick — but it is unbuilt work, not a typo, and it is recorded here rather than fixed
in the same breath as finding it.
