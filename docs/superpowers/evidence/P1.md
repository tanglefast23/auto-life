## Design rules implemented exactly as ruled

- **One reducer commit** (`bar-deltas.ts`): leaf systems emit named contributions; sum-then-clamp-once; the composed Meal+decay tick test is the executable proof.
- **Signed pro-rata effects**: costs accrue with gains; stopping at 99% pays ~99% of the cost.
- **Nap**: startable only below 50 Energy **and inside the wake-relative 60–780 window** (round-1 critics caught the window gating only "effective" — SPEC §6.2 binds startability too); a budget-spent nap is startable but flavor-only; later naps restore 0 **and decay normally** (no Energy-freeze exploit); the wake-boundary reset ships as the pure `crossedWakeBoundary` predicate (tested: fires at wake, never at midnight); `startTimedActivity` refuses budget-bearing activities without an explicit eligibility decision (no fail-open).
- **Sleep**: its contribution is Energy's only writer while asleep; +10/h scaled by nothing.

## Critic round 1 — findings and fixes (all applied)

- **fillStartTick rounding claim was false** (math adversary, 7,504-case sweep: 171 exact-half cases rounded down; the code comment's own cited trap 45×0.7 → 31). Now computed in integers (`frac100 = round(frac×100)`, `floor((ticks×frac100+50)/100)`) — genuinely decimal round-half-up; the schema pins fractions to two decimals; the 45×0.7 → 32 case is a regression test.
- **Nap startability window** — fixed as above.
- Content gate now rejects rates the runtime would throw on (two-decimal refines matching `ratePerMinuteFixed`).
- Reducer hardening: corrupt input bars throw at the commit point; duplicate contribution sources throw (double-apply tripwire).
- `ActiveTimedActivitySchema` validates untrusted DTO restores (mirrors the PRNG snapshot pattern).
- Effective-use schema coherence is bidirectional (budget ⇔ window).
- Suite count corrected (9, not 8); phantom "transcript below" reference removed.
- Process deviation recorded: Tasks 12+13 landed as one commit (the contract prefers one checkpoint per task); P2 returns to task-per-commit.

## Critic round 2 — findings and fixes (all applied)

- **The last float-derived integer**: `durationTicks = ceil(baseMin / mSpeed)` disagreed with exact rational ceil in 99 of 79.2M swept cases (always +1 tick; zero hits for shipped content, but P2 goldens would have frozen it). Now exact integer ceil-division over `(baseMin × 600000, 300000 + energyFixed)`; the baseMin-17 / Energy-18.00 → 25 case is a regression test.
- `startTimedActivity` now guards its bars input (shared `assertValidBars` with the reducer) — no NaN DTOs.
- Content gate magnitude/grid bounds: hourly rates ≤ 100 and two-decimal; `sleepRestorePerHour` positive **on the grid** (≥ 0.01/h — 1e-12 no longer passes as "positive" while quantizing to zero); effect magnitudes ≤ 100; `fillStartsAfterFraction` rounds to ≤ 0.99 (the ~1.0 grid escape is closed). Negative tests for each.
- `napEligibility` throws for window-less activities (a permanently-unstartable answer is a caller bug); `crossedWakeBoundary` validates `wakeTarget` ∈ 0…1439.
- `ActiveTimedActivitySchema` reuses `BarIdSchema` — the drift-prone third bar-enum copy is gone.
- Record corrections from round 2's auditor: `startBelow` was retyped in round 1 from a signed effects map to 0–100 thresholds (shipped content unaffected) — recorded here since the round-1 list omitted it. Erratum: the plan's "nets exactly +10 across **45** ticks" nap figure assumed mSpeed 1.0, which is unreachable under the <50 Energy start gate; the net-+10 property is proven at the sampled duration (50 ticks at Energy 40).
