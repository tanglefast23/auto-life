## Defects found and fixed during P3

**The world rendered nothing until tick 1.** A game opened paused — or simply the first frame — was blank, even though the tilemap, objects, and start position are all known at t=0. `buildSnapshot()` was extracted from `step()` so the loop seeds a snapshot in its constructor. Regression-tested (`the first frame already has a world`).

**The scale solver reported valid steps as inexact.** It iterated fractional scales by subtracting `1/dpr`, accumulating float error: at DPR 3 it produced 5.666667, whose product with 3 is 17.000000000000004. Rewritten to iterate **integer physical-pixels-per-art-pixel**, making exactness structural rather than an epsilon comparison.

**A commit landed without a file it depended on.** `31ed468` staged `src/render` and `src/sim/step.ts` but not `src/sim/render-view.ts`, so that tree was missing the `pose` field `WorldScene` selects sprites from and would not have typechecked. Caught by reading `git status` after committing instead of trusting the add; fixed in `fde218e`. Working-tree green is not commit green.

## Adversarial loops (Joe's cadence: me → codex 5.6-sol max → me → codex 5.6-sol max)

### Loop 1 — self. 3 bugs

Probed pure functions with hostile input rather than re-reading code.

1. `advancePhase(phase, NaN, m)` returned NaN, **and NaN is permanent** — every later `phase >= 0.5` comparison is false against it, so the walk loop froze on frame 0 for the rest of the session.
2. A backwards frame timestamp produced a **negative** phase (−0.5), outside the documented [0,1) contract. RAF timestamps do step backward in practice.
3. `solveScale` chose k=1 at DPR 2 on a narrow window → **scale 0.5**, silently drawing a half-size world while reporting `tooSmall: false`. Sub-native rendering is the v1.1 sharp-bilinear path (SPEC §11.5), not the desktop one.

Confirmed *not* bugs while probing: pause discards the banked accumulator, exactly-at-cap is not treated as dropped, `mSpeed 0` correctly holds the frame, a stale travel path degrades to a valid quad, and a 7-day 10,080-tick run drops zero frames.

### Loop 2 — codex CLI, gpt-5.6-sol at max reasoning. 2 blockers + 6 majors

Every claim was reproduced before being accepted. Both blockers were **worse than reported**.

- **BLOCKER** — travel was published from *post-step* state. Probe of the first journey: tick 1 reported the sim at (6,2) while it stood at (4,2); the arrival tick reported `travel: null` so the final leg teleported; and the entire toilet→sink journey was one tick reporting `processed: 'travel'` with `travel: null` — 100% teleport, no interpolation data at all.
- **BLOCKER** — visibility resume kept the pre-hide RAF timestamp, so the first resumed frame carried the whole away-duration and advanced 8 game minutes against a contract that says zero. **I had observed those 8 ticks in the browser earlier and wrongly called it the per-frame cap working correctly.**
- Snapshot **aliased live sim state** — mutating `snapshot.render.travel.path[0]` mutated the running game (`readonly` is compile-time only).
- `setSpeed` always zeroed the accumulator, so mashing the already-active speed reset progress forever and the clock never advanced.
- `Atlas` omitted `sampling`; Skia defaults to **linear**, blurring every pixel edge whenever §11.5's scale ≠ 1.
- Walk phase used real-time delta → at 4× the sim slid on 1× strides; paused, its legs kept cycling.
- `activityProgress` was derived, published, and **never drawn** — §11.1's progress ring did not exist, and the test named "drives the ring" only checked the DTO.
- The HUD computed the band then discarded it: the 40–69 edge tick was never rendered and "pulse" was a static border.
- Per-frame React state bump (~43,200 reconciliations per 1× day, continuing while paused).

### Loop 3 — self. 2 runtime defects

Loops 1–2 read code and probed pure functions; this pass **ran the exported build and read the browser console**, which surfaced two defects invisible to both static review and unit tests: `useNativeDriver: true` warning on every mount under react-native-web (silently falling back to JS), and the deprecated `SkPath.addCircle()` scheduled for removal in a future Skia release. Console is clean after both fixes.

### Loop 4 — codex CLI, gpt-5.6-sol at max reasoning. 1 blocker + 10 majors + 1 minor

Run with all prior findings and the two accepted deferrals excluded from scope. Three claims were probed before acceptance; all three reproduced exactly.

- **BLOCKER** — pause carried **raw milliseconds**, not normalised progress. Loop 2's fix rescaled via `msPerTick(effectiveSpeed)`, which is `Infinity` while paused, so the rescale silently no-opped. 400 ms banked at 1× survived a pause and met 4×'s 125 ms tick: the next `advance(0)` ran **three ticks the player never saw**, and alpha jumped 0.8 → 0 → 1. My loop-2 fix had handled *system* pause and missed *player* pause.
- `activityProgress` could never reach 1 — post-step `current` is null on the completion tick, so a 3-tick activity published `0 → .33 → .67 → null` and the ring vanished at 67%. Same class as the travel bug, same fix.
- Facing used `path.length` while the interpolator used `path.length - 1`, so on a multi-corner journey the sprite faced down while sliding left.
- Idle returned `down` unconditionally **while the RenderView contract already promised "holds last value when still"** — code contradicting its own comment.
- **`WorldScene`'s RAF effect listed `view` in its deps.** `view` is a fresh object every tick, so the effect remounted 2–8×/second and reset `phase` and the frame timestamp each time — *the walk cycle never ran, it just restarted*. `watched-day.test.ts` cannot catch this: it never mounts React.
- Snapshots were mutable — `snapshot.bars.energy = -999` stuck and poisoned every HUD consumer until the next tick.
- `scale.ts` reserved 48 px for a seven-row Health panel that measures ~148 px, so the HUD overlaid the top of the world including the starting character, while `tooSmall` read false.
- The main Health bar was pinned to `band="normal"`, so a Day-1 Health of ~60 never showed the 40–69 warning on the one bar a player looks at first.
- `verify` never rebuilt or diffed the committed atlas. Added `art:check`, which **immediately caught that the committed atlas predated the outline fix** — the gate earning its place on its first run.
- World placeholders used Ink outlines; design.md §3 Track B reserves Ink for UI. The palette validator was green because it checks colours, not roles.

Also corrected an overclaiming comment of my own: `WorldScene` said frame maths ran off the JS thread. The **paint** is off-thread and React is not involved per frame, but the maths runs in a JS RAF callback. Moving it to a frame worklet is P6's performance pass.
